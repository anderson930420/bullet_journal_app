# Bullet Journal App — Developer Workflow

## Repository Branches

- `main` — stable, reviewed only
- `worktree/*` — isolated task workspaces (auto-generated by Hermes Kanban)
- `backup/*` — emergency restore points

## Git Workflow

### Making Changes

1. All tasks run in isolated `worktree/` workspaces.
2. Changes stay in the worktree branch until human review approves.
3. Human reviews the diff and decides to merge or discard.
4. Only human-approved changes reach `main`.

### Prohibited Without Explicit Human Approval

- `git push` to `origin`
- `git merge` into `main`
- Direct commit to `main`
- `git reset --hard` on `main`
- History rewrite (`git filter-repo`, BFG, etc.)
- Force push to `main`

### Analysis / Read-Only Tasks

These tasks must never modify the repo. They must:
- Use isolated `worktree`
- Write artifacts to `~/.hermes/task-artifacts/<TASK_ID>/`
- End in `blocked / waiting_for_human_review`
- Never run: `git rm`, `git commit`, `git push`, `git reset`, `git clean`, `git filter-repo`

## Artifact Policy

All tasks must produce artifacts under `~/.hermes/task-artifacts/<TASK_ID>/` before completing or blocking.

Required artifact files:
- `worktree_info.txt` — `git worktree list` output
- `git_status.txt` — `git status --short --untracked-files=all`
- `completion_report.md` — task summary and findings

## Database Policy

- Local SQLite databases (`.db`, `.sqlite`, `.sqlite3`) are sensitive by default.
- Do not commit them unless explicitly required for test fixtures.
- Do not dump private DB contents into artifacts.
- Use schema + row counts only.
- If a `.db` file is tracked and should be untracked, request explicit human approval before history rewrite.
